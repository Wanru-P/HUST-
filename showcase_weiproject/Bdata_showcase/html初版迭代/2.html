平台现状

  • 规模空前：公开模型已超 314 万，全球最大开放模型托管平台

PART 01 / 问题与数据

Windows 环境适配：三个典型坑与对策

坑 1
winutils.exe

缺失导致 Spark 无法启动

Spark 在 Windows 上依赖 Hadoop 的 winutils.exe， 官方不提供，网上流传的二进制版本常与 Hadoop 版本不匹配， 引发 UnsatisfiedLinkError 或静默失败。

✅ 对策：使用 hadoop-bare-naked-local-fs —— 纯 Java 实现的本地文件系统，完全绕过 winutils，不依赖任何原生二进制。
坑 2
时区漂移

跨月边界时间戳平移

本机时区与 UTC 不一致时，跨月边界的时间戳会发生平移， 导致同一条数据在两次运行中落入不同的月份， 月度统计结果对不上。

✅ 对策：锁定 UTC 时区， 所有时间解析统一在 UTC 下进行，跨月边界严格一致。
坑 3
内存压力

driver OOM 与系统卡死

314 万行全量 join + 图构建时 driver 容易 OOM， 但内存调太大又会压垮开发机，找不到稳定的工作点。

✅ 对策：driver 锁 3g， 配内存告警 + mem_pressure 标记隔离，超限步骤单独跑。
📌 经验沉淀：这三条对策都具有通用性，可作为"在 Windows 上跑 Spark"的 可复用工程模板——不止服务本项目，也可供后续同学直接参考。

PART 02 / 核心发现

RQ2下载注意力的极端集中

洛伦兹曲线 · Lorenz Curve 越弯 = 越集中
曲线严重偏离对角线 → 基尼系数高 → 注意力高度集中
极端长尾
绝大多数模型下载量极低
幂律尾部
双对数坐标下近似直线

核心结论

  • 极端长尾：绝大部分模型下载量极低，头部模型占据压倒性份额
  • 基尼系数高：洛伦兹曲线严重偏离对角线，基尼值接近上界
  • 幂律特征：下载分布不符合正态，而是典型的重尾分布
  • 生态含义：注意力高度集中在少数"明星模型"上，长尾几乎无人问津

为什么用洛伦兹曲线

洛伦兹曲线是经济学衡量收入不平等的标准工具：横轴人口累积占比，纵轴收入累积占比。 我们把它迁移到下载注意力分配问题上——横轴是模型累积占比，纵轴是下载量累积占比。 对角线 = 完全平均，越弯 = 越集中。

Theil 指数是可分解的不平等度量。它的独特之处在于： 总不平等 = 组间不平等 + 组内不平等，严格可加。 这让我们能回答"集中度主要来自哪里"， 而不只是"集中度有多高"。

边语义（关键）

  • src = 底座模型，dst = 衍生模型
  • children_count = 出度 = 被多少模型直接当 base
  • 方向不可反：底座 → 衍生，反向无意义

为什么不是树

树要求每个节点只有一个父节点、无环。但实际网络中： ① 多父合并（一个模型同时以多个模型为底座）、 ② 底座互指（A 声明 B 为底座，B 也声明 A）、 ③ 环（SCC 的存在）。 这些使得它必然是一个有向图。

可比性判定（关键设计）

comparable = true 表示有资格参与跨任务比较， 而不是"样本量够大"这么简单。判定条件：

  • n_models ≥ 200 —— 样本量门槛，避免小样本噪声

工程亮点：可复现性与工程纪律

📌

固定快照 · 权威来源唯一

commit + SHA-256 双重校验；所有结果以 results_manifest.json 为权威来源，任何人重跑得到一致数字。

🔒

spark 与 local 两套引擎产物落在不同目录，切换引擎不会污染已有结果，方便对照验证。

🎛️

driver 内存锁 3g，配内存告警 + mem_pressure 标记隔离超限步骤。

🛡️ 规模档哨兵处理

real_cold_touch 行数比 100% 档还多 5 行，按"至少两个分区档中取行数最大者"统一挑选，避免哨兵行误判。

📊 指标诚实性

shuffle / CPU 指标取不到记空值，绝不写 0；关闭 AQE 以避免 shuffle 被系统性低估。

✅ 12 图完整性守卫

未来展望：三个方向

01

增量快照追踪

当前是单快照横截面分析。接入多个时间点的 Hub 快照，可以做真正的纵向演化追踪：

  • 家族如何生长？
  • 明星模型的注意力如何衰减？
  • 新任务如何从长尾走向主流？
时间维度 · 从横截面 → 纵向追踪
02

图算法扩展

在谱系网络上扩展更丰富的图算法：

  • PageRank —— 谁是影响力枢纽？
  • 社区发现 —— 是否存在模型家族群落？
  • 传播模拟 —— 新模型如何沿谱系扩散？
关系维度 · 从结构 → 影响力
03

因果与可视化

两个方向同步推进：

  • 从统计关联走向更严格的因果识别
  • 可视化从有界子图扩展到可下钻全量网络
  • 支持按任务 / 时间 / 家族多维筛选
方法维度 · 从相关 → 因果
