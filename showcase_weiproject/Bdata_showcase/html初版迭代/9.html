平台现状

  • 规模空前：公开模型已超 314 万，全球最大开放模型托管平台

💡 研究视角： 本项目把 Hugging Face Hub 当作一个"超大规模社会系统"来研究—— 不是看单个模型的性能，而是看整个生态的结构、分配与关系。

💡 核心思路：用纯 Java 实现替代原生二进制，彻底绕开 Windows 生态缺口。
1
winutils.exe 缺失 Spark 无法启动
官方不提供 winutils，网上流传的二进制常与 Hadoop 版本不匹配， 引发 UnsatisfiedLinkError 或静默失败。
✅ 对策：使用 hadoop-bare-naked-local-fs —— 纯 Java 本地文件系统，完全绕过 winutils。
2
时区漂移 月度统计错位
本机时区与 UTC 不一致时，跨月边界的时间戳会平移， 同一条数据在两次运行中落入不同月份。
✅ 对策：锁定 UTC 时区，所有时间解析统一在 UTC 下进行。
3
内存压力 driver OOM
314 万行全量 join + 图构建时 driver 容易 OOM， 但内存调太大又会压垮开发机，找不到稳定工作点。
✅ 对策：driver 锁 3g， 配内存告警 + mem_pressure 标记隔离。
📌 经验沉淀： 这三条对策都具有通用性，可作为"在 Windows 上跑 Spark"的可复用工程模板。

⚖️RQ2下载注意力的极端集中

洛伦兹曲线 · Lorenz Curve 越弯 = 越集中
曲线严重偏离对角线 → 基尼系数高 → 注意力高度集中
极端长尾
绝大多数模型下载量极低
幂律尾部
双对数坐标下近似直线

核心结论

  • 极端长尾：绝大部分模型下载量极低，头部占据压倒性份额
  • 基尼系数高：洛伦兹曲线严重偏离对角线
  • 幂律特征：下载分布不符合正态，而是重尾分布
  • 生态含义：注意力高度集中在少数"明星模型"上

为什么用洛伦兹曲线

洛伦兹曲线是经济学衡量收入不平等的标准工具。我们把它迁移到下载注意力分配问题上—— 对角线 = 完全平均，越弯 = 越集中。

PART 02 · 核心发现

🔧RQ3图算法：如何处理有向图中的环

1
找 SCC · 强连通分量
识别图中所有强连通分量，共 10 个规模 >1 的 SCC
2
折叠成超级节点
把一个环折叠成单个节点，消除循环依赖
3
凝聚 DAG
得到有向无环图，可在其上执行路径算法
4
最长路径求解
计算 subtree_height 与 root_depth 两个长度指标

subtree_height

凝聚 DAG 上从该节点到汇点的最长路径（边数）。不是树的层数。

用途：判断一个底座"衍生链能走多远"

root_depth

凝聚 DAG 上从源点到该节点的最长路径，衡量它离"最初底座"有多远。

用途：识别模型的"血缘深度"

leaf_child_share

直接子节点中自身无出度的比例，刻画家族的"叶化程度"。

用途：家族是"星型爆发"还是"链式演化"
⚠️ 诚实报告： 血缘缺失率 71.74%，未声明血缘 ≠ 没有血缘。 谱系在快照边界被截断，因此所有后代类指标都是 下界。

🚀未来展望：三个方向

01

增量快照追踪

当前是单快照横截面分析。接入多个时间点的 Hub 快照，可以做真正的纵向演化追踪：

  • 家族如何生长？
  • 明星模型的注意力如何衰减？
  • 新任务如何从长尾走向主流？
时间维度 · 从横截面 → 纵向追踪
02

图算法扩展

在谱系网络上扩展更丰富的图算法：

  • PageRank —— 谁是影响力枢纽？
  • 社区发现 —— 是否存在模型家族群落？
  • 传播模拟 —— 新模型如何沿谱系扩散？
关系维度 · 从结构 → 影响力
03

因果与可视化

两个方向同步推进：

  • 从统计关联走向更严格的因果识别
  • 可视化从有界子图扩展到可下钻全量网络
  • 支持按任务 / 时间 / 家族多维筛选
