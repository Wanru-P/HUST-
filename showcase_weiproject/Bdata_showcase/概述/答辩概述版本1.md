# Slide 9 · 难点深挖：Windows 上跑 Spark

- 坑：Spark 默认 `RawLocalFileSystem.setPermission` 在 Windows 上只有两条路——`hadoop.dll` 或 `winutils.exe`，且 `core-default.xml` **没有任何开关能关掉**（反编译 Hadoop 源码才确认）
- 解法①：换纯 Java 的 `BareLocalFileSystem`，`setPermission` 在 Windows 上直接空操作
- 解法②：时区必须锁 UTC，否则 23 点的 UTC 记录被推到下个月
- 解法③：全局排序改"先聚合频数表、再查表还原排名"，绕开单分区 shuffle

# Slide 10 · 算法正确性

- Gini 用**频数加权秩公式**精确计算，不是采样近似
- 三种独立口径（秩式 / 频数加权 / Lorenz 梯形积分）交叉验证，最大偏差 ≤ 4.4e-16（浮点误差级）
- 两种下载口径严格区分：近 30 天 vs 历史累计，相差 27 倍，绝不混用
- 56 项契约测试 ✓ + 114 项一致性检查 ✓

# Slide 13 · RQ3 模型谱系网络

- 血缘边 919,839 条，节点 931,066 个——"一张 93 万节点的 fork 关系图"
- 最大底座 `FLUX.1-dev` 直接派生 **43,419** 个模型——"一个祖师爷，四万多个 fork 它的项目"
- 关系四种：finetune（微调）、adapter（适配器）、quantized（量化）、merge（合并）
- 图算法 6 步全跑完：连通分量 42,890 个、PageRank 双向、标签传播 126,431 个社区
- 细节：节点数取去重并集 93 万，不能把"底座数+衍生数"直接相加（会重复算 4 万多个）

# Slide 14 · RQ4 统计关联（MLlib）

- 目标：预测 `log1p(下载量)`
- 先切训练/测试（seed=42，两者零交集），**绝不拿测试题练手**
- 结果：RandomForest R²=0.663 > GBT 0.631 > LinearRegression 0.418
- 最强关联特征：`tag_count`（标签数量）0.413 > `library_top`（用什么库）0.194 > `likes_log`（点赞）0.151
- 诚实定位：点赞和下载是同一时刻数据，**重要性 ≠ 因果 ≠ 预测**
- 【图：fig09_ml_importance.png】

# Slide 17 · 创新点（4 条）

1. **频数加权 Gini 精确口径**：先数频数再算，绕开全局排序，还保证精确
2. **谱系边语义严格保留**：方向不搞反，外部父模型完整留着
3. **GraphFrames 与 Spark 双轨 + 逐步骤落盘续跑**：长任务能断点续跑，每步耗时如实记录
4. **单一结果清单驱动所有交付物**：一个数据源，报告图看板全对齐
